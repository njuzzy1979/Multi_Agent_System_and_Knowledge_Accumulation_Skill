# 知识沉淀机制总纲

## 分类学（先有分类学，再有机制）

知识按「诞生的场景与形态」分六层渠道，**排他职责边界**（同一 SOP 不散落多处互相漂移）：

| 渠道 | 职责 | 性质 |
|---|---|---|
| 项目主指令文件（CLAUDE.md） | 项目事实（semantic）+ 路由表 | 每 session 加载，要省行数 |
| 会话记忆（memory） | 用户偏好 + 一次性事实 | 个人级 |
| 工作日志（CHANGELOG/战役报告） | episodic 证据层 | **本库 provenance 源**，职责不动 |
| **本知识库（.claude/skills/ 整体）** | **procedural（怎么做）唯一权威层** | 症状 → 条目两步定位 |
| 代码注释/测试 | 局部知识（随代码走，不进库） | 就近维护 |
| drafts/ | 未采纳草稿隔离区（库内隔离分区，单列以示零污染属性） | 零污染（见 drafts 门禁） |

提炼方向**单向**：日志产证据 → 证据经人工采纳升格为程序性知识。方向性防止知识库变成日志副本。

## 四模板（按知识诞生场景路由，机械不做主观判断）

| 来源特征 | 模板 | 核心字段 |
|---|---|---|
| 实施报告 / 修复判例 | 一·修复 | 症状 / 根因 / 步骤 / 先例 |
| 方案选型节 / 非目标节 | 二·设计 | 决策 / 备选与排除理由 / 适用边界 |
| 审查报告 High/Medium 发现 | 三·审查 | 缺陷模式 / 发现方法 / 拦截案例 / 适用场景 |
| 根因反转 / 排除逻辑结论 | 四·认知 | 先验假设 / 证伪证据 / 修正结论 / 方法论 |

路由键是「这份材料**从哪来**」，不是「我觉得它像什么」——机械路由消除提炼者的主观判断空间。全文与设计精髓：references/四模板.md。

## 双时机提炼

### 即时通道（不等收官；首次发现即沉淀——时机稍纵即逝，下一个 turn 推理上下文就没了）

1. **审查轮回（origin=review-round）**：收到审查报告时，即时判定 High/Medium 发现是否为「可命名的普适缺陷模式」（非本战役特有）——是则当场 Write 草稿。
   **机械锚**：收到审查报告**必** Grep 正文 `缺陷模式|普适|反模式|高危|Critical|High`，命中即进判定流程——不依赖「觉得重要才做」。
2. **根因反转（origin=reversal）**：侦查结论推翻先验定性时，在**采纳结论的同一回复内**按模板四写草稿。
   依据：「反转时刻的推理结构事后重建必然失真」。**机械锚**：采纳反转结论的同一回复内自查已落草稿或说明非反转。
3. **「可沉淀知识」节（轻量钩子）**：派发任务书末尾固定附一句——「过程中发现可复用的模式/技巧/教训，请在报告末尾单列『可沉淀知识』节（条数上限见总索引维护规则，每条一句话+出处）」。零结构改动，收官时优先消费。

### 收官通道

- **sop_hint 机械锚**：收尾时 Grep 本战役核心症状词于 `.claude/skills/` 全域（含 drafts/ 与 methodology/，**排除 knowledge-capture/；命中判定以 frontmatter 与路由表行为先例，正文普通词命中不计**——防自指与假先例把加急常态化）——**命中 ≥1 即「第 2 次同类」**→ 归档指令带 `sop_hint: true`（加急，必产草稿）。频次判断外化为文本检索，绕开 LLM 无跨 session 记忆的根本局限。
- **恒跑轻扫兜底**：每次收官固定 ~1 分钟轻扫（检查报告是否含「根因/修复/复发/排除/反转」类可结构化结论），无则报「无」——冷启动期 grep 必零命中，由它保底，提炼机制不退化为依赖自觉。

### 呈报协议（双保险）

即时草稿必须在**下一战役节点**（收官呈报/下一用户汇报）显式提及待采纳；**收官机械锚：每次收官列 drafts/ 文件名日期与「呈报=<日期>#<次数>」字段，超期草稿（阈值见总索引维护规则）逐条呈报请裁决；已呈报 ≥2 次未裁决的草稿降频为每 3 次收官呈报一次（超期清理前必呈报保底）**——「季度清理」由此外化为每次收官的机械日期判定（不依赖「记得季度这件事」的自觉），呈报后由人工批量裁决。双保险保证每份草稿至少一次进入人工视野且不被重复呈报钝化（治「永不进视野」与「呈报狼来了」两断点）。

## drafts 门禁（错误知识比没有知识更糟）

- 定位：未采纳草稿——**转正须用户显式批准，未采纳零污染**（不进总索引/不进路由表/不被 description 触发）
- 命名：`draft-<模式名>-<YYMMDD>.md`；头部 `origin=<review-round|reversal|wrapup>`
- 正文按四模板之一组织（草稿与转正同构，转正=移动+索引加行，无改写成本）
- 流转四规则：①落盘前对照**总索引既有条目与 drafts/ 现存草稿**去重（只增补不重复）②双保险呈报（上节）③采纳→转正+总索引加行（**origin 头部行保留**，成为条目 provenance 的一部分——维持「转正=移动+索引加行」零改写承诺）；未采纳超期（阈值见总索引维护规则）→季度清理 ④与现有条目矛盾 → 头部标 `CONFLICT` 待人工仲裁，**提炼者不仲裁**

## 人机边界（宪法级原则）

- **LLM 只做机械抽取**：压缩 / 结构化 / 去重 / 路由
- **人保留**：采纳 / 失效判定 / 冲突仲裁——错误知识污染所有未来 session，比没有更糟，采纳必须人工
- 入库判据：有**验证证据**（验证通过 / 生产验证 / 审查拦截实证）才 active；纯理论推演标 draft

## skill 写作规范（三级渐进披露）

- **L1 description**（常驻上下文的唯一部分——**每个 session 都在烧上下文，故窄触发：宁可不触发也不误触发**）：写「何时用」不写「是什么」；症状特征含**错误码/表名/行为样例**（精确串既提高命中又防误触发）；触发样例用引语体（模拟用户/下游 agent 的原话）；draft 状态警告内置在 description（防窗口期风险）
- **L2 正文**行数上限为硬约束（数值以总索引维护规则为唯一权威，超限拆 references/）；高频核心放这里——L2 是 Read 一次的成本，可承载比 L1 多得多的细节
- **L3 references/**：判例长文 / 命令模板 / 脚本，按需读（主动下钻的成本）；每个 references 目录带 README 登记表（文件/来源条目/主题——让 L3 也可 grep 可审计）
- **元信息块四字段同构**（索引可聚合的前提）：`状态=<active|draft|stale>` ｜ `最后验证=<YY-MM-DD（附验证性质）>` ｜ `适用版本` ｜ `源材料=<路径>`；状态三档：active（有验证证据）/ draft（骨架就位，采纳门禁未过或首验未发生）/ stale（复查不达标或超期未验证，阈值见总索引维护规则）；**「最后验证」语义=最近一次触发场景实测日期（非装饰性复查）**

## 首批存量挖掘（Phase A/B 两段式）

- **Phase A 机械初筛**：LLM 扫描全量史料（CHANGELOG/工作日志/战役报告），大文本**强制分批**（防上下文溢出）；产出三值分流：新 skill 候选 / 充实既有 / 仅存档——**不做采纳判断**。执行主体/分批规则/挖掘 prompt/输出表格式 → 操作卡见 references/索引与路由模板.md §七
- **Phase B 人工终审**：用户只审**争议项与新提案**（全量清单不呈报——审阅预算意识：人类裁决是全体系最稀缺资源）；诞生门槛成文：**判例 ≥3 且步骤可复述**（数量+质量双卡，防低价值条目稀释）
- 榨取不搬迁：episodic 原文不动，provenance 双向回指

## 索引与路由

双索引分工 + 单一权威源设计（防漂移与契约冲突）→ 全部规则与模板见 references/索引与路由模板.md。要点：总索引 README 是唯一权威全量表；CLAUDE.md 路由节是高频样例（滚动淘汰）；**数值权威三类分治：索引/行数/滚动类只在总索引维护规则处定义一次；知识诞生门槛（判例 ≥3）唯一权威在本文 Phase B 节；管线运行类（并行上限/重试次数）唯一权威在 CLAUDE.md集成段 硬性规则——三类之外的位置一律单向引用不自报数字**。

## 非目标（克制清单）

- 不引入外部框架（只借概念不带依赖）
- 不建向量知识库（百条级 markdown + grep + 索引三方交叉验证优于 RAG）
- 不做全自动采纳（人工门禁是安全机制不是性能瓶颈）
- 不建新存储层（既有渠道的出路是统一索引+分层复用，新存储是重组不是加层）

- [ ] 草稿全部带 origin 标记且已去重

- [ ] 转正条目全部经人工采纳且总索引已加行
- [ ] 索引/路由的行数与滚动规则只在维护规则处定义
