## Agent 调用规则（v1.1 通用版）

**启动锚**：收到代码改动/代码修复/代码设计类任务，**先声明轨道再动手**——直通（无行为歧义微改：typo/注释/格式，不走管线直接改，顺带发现走登记）/ 机械小改（④⑤）/ 轻量（③④⑤）/ 重型（全链）。走管线时**本对话即编排器**；首次担任编排器的 session，启动管线前先 Read `.claude/skills/knowledge-capture/references/六件套管线手册.md`（判定生成与收官清单的权威）。

主力管线（重型走全链；轻量跳过设计直达审查）：

| 阶段 | agent | 档位建议 | 说明 |
|---|---|---|---|
| ① 侦查 | `eng-recon` ×N 并行 | sonnet | 子模式 tech/data/research 各派实例，产 r1_/r2_ 报告落盘 |
| ② 设计 | `eng-arch` | opus | 复杂战役才走；小修复可跳过 |
| ③ 对抗审查 | `adversarial-reviewer` | opus | 默认假设方案有缺陷；先立后破 |
| ④ 实施 | `eng-implementer` | sonnet | 按单任务规格编码，模仿现有模式 |
| ⑤ 交叉验证 | `eng-validator` | opus | 方案↔diff 逐条对照；首轮 FAIL 回炉是设计内防线 |
| ⑥ 归档 | `eng-documenter` | sonnet | 文档同步 + 知识提炼机械路由 |

硬性规则：

1. **红线域守卫强制插入**：任何触碰红线域（{{项目声明；无红线域填「无」→ domain-guard 天然休眠；例：真实资金 / 安全 / 用户隐私 / 生产数据删除 / 付费计费逻辑}}）的代码路径，审查阶段一律过 `domain-guard`（重档），不因「改动量小」而降档。典型触发点清单（**唯一权威位**，domain-guard 模板不维护副本；新增触发点只改此处并随演进更新）：{{文件名/类名/关键字模式，例：下单入口 `orders_*.py`、扣费类 `<Billing|Charge>`、删除类迁移脚本}}。
2. 不确定用哪个 agent 时默认不指定 model（继承主对话档），不主动降轻档。
3. 重档审查/验证/守卫环节**独占运行不并行**；轻环节并行上限按平台实测锚定（3-4 并行为已验证安全量级）。
4. 编排器是**主对话的职能**（depth-0），不是可分派的子 agent 角色；**战役计划先落盘 `<战役报告目录>/campaign.md`**（首个 dispatch 前 Write，含状态行区——上下文压缩后的恢复锚）；子 agent 输出「落盘即遗忘」（详情 Write 到 `{{战役报告目录，例：results/exec-detail-<战役名>/}}`，final report 只允许极简三行——见 `.claude/skills/knowledge-capture/references/六件套管线手册.md`）。
5. 分派对账：agent 派发/完成按 dispatch/done/expect/check 四事件协议登记（协议、最小实现与登记命令模板见 `.claude/skills/knowledge-capture/references/六件套管线手册.md` §6；真实派发后立即登记）；**完成判定锚产物文件存在性，不锚自述**；宿主支持 hooks 时可用 PreToolUse/SubagentStop 将登记与校验机械化（样例见手册 §6）。
6. 单 agent 不设名义硬超时，按**战役级 token/时长预算**管理，超预算由编排器主动终止。
7. 重环节（审查/验证/守卫）门禁失败重试 1 次 → 仍失败 → 问题登记（P0 阻塞级）+ 停流水线呈用户；轻环节（侦查 ×N）部分实例失败=保留成功产物+标注覆盖缺口+补派单实例（手册 §2 铁律 4）；**禁止虚报 agent 状态**（真实派发后才能写 RUNNING）。
8. 问题分级路由：P0（阻塞）/ P1（简单，直接修）/ P2（中等，修后记录）/ P3（需决策，上报）。
9. 侦查子任务调用预算（唯一权威）：tech ≤15 次 / data ≤10 次 / research 每维搜索 ≤4 次换词、五维合计 ≤20 次——超预算按降级路径上报，不继续烧。

## 知识沉淀提炼规则（v1.1）

**收官判定（含机械锚）**：战役收尾时 Grep 本战役核心症状词于 `.claude/skills/` 全域（含 drafts/ 与 methodology/，**排除 knowledge-capture/**；**命中判定以 frontmatter 与路由表行为先例，正文普通词命中不计**——防自指与假先例把加急常态化）——命中 ≥1 即「第 2 次同类」，归档指令带 `sop_hint: true`（加急，documenter 必产草稿）；documenter **每次收官恒跑**轻扫兜底。

**即时沉淀（不等收官；首次发现即沉淀）**：
① 审查报告到达时，即时判定 High/Medium 发现是否为可命名的普适缺陷模式（非本战役特有）——是则当场 Write 草稿（origin=review-round）；机械锚见上节。
② 侦查结论发生**根因反转**（推翻先验定性）时，同点位按模板四（认知类）写草稿（origin=reversal）——反转时刻的推理结构事后重建必然失真。
③ 派发任务书末尾固定附：「过程中发现可复用的模式/技巧/教训，请在报告末尾单列『可沉淀知识』节（条数上限见知识库总索引维护规则，每条一句话+出处）」。

**人机边界**：LLM 只做机械抽取（压缩/结构化/去重/路由）；**采纳/失效判定/冲突仲裁留人**——错误知识污染所有未来 session，比没有更糟。即时草稿须用户采纳方可转正，且须在下一战役节点（收官呈报/下一用户汇报）显式提及待采纳；季度清理（阈值见总索引维护规则）前收官步骤兜底重扫。

**四模板与全部机制规则**：`.claude/skills/knowledge-capture/SKILL.md`（总纲）+ 其 references/（四模板全文/索引模板/管线手册/判例精选/本集成段的权威源）。
