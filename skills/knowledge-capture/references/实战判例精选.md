# 实战判例精选（12 条跨领域判例）

> 版本 v1.0
> 每条 = 通用规则 + 实例简注。按普适度排序。这些判例是体系中每条规则背后的「为什么」——规则可改，判例背后的教训不可绕。

---

## 1. 「成功」的各态失败（静默失败族）——最强判例族

**通用规则**：验证「成功」必须区分**正常成功 / 空转成功 / 降级成功**三态，退出码只表达第一态。

四个实例：
- 探测点与主链接口**不同构** → 探测长期 healthy + 主链经常挂，静默并存
- 容错链**静默降级** → 兜底成功落库 ≠ 数据健康，判「零损失」必下探备用分支的产出质量
- rc=0 但 0 行——**无事件 0 条与失败 0 条不可分**，部分失败被吞
- rc=0 但行为零变化

## 2. 自查与意图验证必须分离

**通用规则**：同一 agent 不得同时担任实现与验收；验证首轮失败率是**健康信号**而非事故（预设回炉预期，防验证 FAIL 触发流程恐慌）。

来源：agent implementer 定义「自查只覆盖能不能跑，意图验证交 validator」+ 集成段管线表 ⑤ 行「首轮 FAIL 回炉是设计内防线」。

## 3. 验证必须带产物/精确数字

**通用规则**：一切验证结论挂可复核证据（数字/diff/链接/文件:行号），印象估算不算。

来源：agent validator 逐条对照方案↔diff；eng-recon data 子模式「『约 10 亿行』不如 SELECT COUNT(*)」；数据验证「实际值 vs 基准值」且**基准从历史推算不凭印象**；research「每条引用必须实际验证过」。

## 4. 机械锚防自觉退化——制度落到 LLM 行为学的关键发明

**通用规则**：对 LLM 的行为要求必须配**机械可执行的触发器**（收到 X 必做动作 Y：Grep/对照/落盘），「依赖自觉」的规则在高压路径必然失效。

来源：知识沉淀体系——收审查报告必 Grep `缺陷模式|普适|反模式|高危|Critical|High`；收尾必 Grep 症状词；采纳反转结论同一回复内自查草稿。每个关键机制均配机械锚。

## 5. 根因反转即写

**通用规则**：认知翻转事件比常规修复高一个优先级，**现场即时沉淀**——反转时刻的推理结构事后重建必然失真。

来源：两判例（2026-09）：某方案定性「结构性不可测」→ 实为「coverage 错登」，1 行 UPDATE 解锁 16 条规则；好规则被评估实现缺陷误杀 → 实现重设计后翻案。

## 6. 确定性防线优先于概率防线

**通用规则**：能写成规则检查的守卫不交给 LLM；LLM 守卫只补规则覆盖不了的语义层。

来源：数据安全双防线——「第一道防线确定性（Hook+标志文件硬阻断），第二道防线概率性（LLM 审查）」。顺序不可换。

## 7. 窄职责 + 负面约束定义 agent

**通用规则**：负面约束比正面职责更防角色漂移；一个 agent 的「不做什么」清单至少与「做什么」等长。

来源：全部 9 个 agent 定义——不评判方案/不评判风格/不做主观判断/只检查不修改/不发明新模式/不仲裁。

> v1.0 注记（2026-10-01 自审登记）：六件套重构合并子模式后正面指令密度上升，七定义负面约束实测 3:1~6:1 未达等长；隐性负面约束（不猜测/不凑数/不就地修复/不仲裁等）散见于通用纪律节。已知取舍，后续版本按本判例归并显式化。
> 2026-10-02 已按本判例完成归并（regen-v1.0 战役）：七定义负面约束现 10-14 条，对正面职责比例 0.74-0.87，全部 ≥2/3 门槛。

## 8. 模仿现有模式，不发明新模式

**通用规则**：代码库一致性优先于局部最优；新风格进入代码库必须走设计层，不在实施层顺手带入。

来源：agent implementer 铁律——先 Grep 目标符号的现有同类实现作模板（有封装就用、有日志函数就不 print）。

## 9. 调用痕迹治理（死定义清理）

**通用规则**：agent 定义是**负载不是资产**，定期按实际调用痕迹清退；管线形态以实测使用分布为准（~88% 走主力链）而非设计完备性。

来源：2026-09-29 死定义清理——21 个定义砍到 9 个（12 个三周零调用痕迹 git rm，含两个编排器剧本）。

## 10. 同名双轨 = 通用版 + 领域补丁包

**通用规则**：领域定制走「补丁节追加」（硬约束速查节+输出纪律节）而非整文件复制——通用骨架可同步升级。

来源：全局版与项目版同名 agent 并存（项目版=通用骨架+领域节），CLAUDE.md 明文「同名双轨时优先项目版」。

## 11. expect 产物存在性对账

**通用规则**：完成判定**锚产物存在性，不锚自述**（与判例 3 同根：不采信实施报告自述）。

来源：agent_reconcile——dispatch/done/expect/check 四事件协议；expect 字段产物文件存在自动视为完成。

## 12. 双索引分工防漂移 + 治理机制自反一致

**通用规则**：任何治理机制的设计必须**显式论证自己不会复发它要治的病**（知识库治主指令文件膨胀，自身设计必须内建防膨胀：行数上限+滚动淘汰+单一数值权威源）。

来源：知识路由双索引（唯一权威全量表 + 高频样例表滚动淘汰）；反例自判例——批判信息膨胀的方案自己设计数百行呈报直灌，被审查拦下后固化为「用户只审争议项与新提案」呈报纪律。本体系成型时又实测抓到一次（两处行数上限数字不一致），以「单一权威源」根治。

## 使用建议

- 新项目接入时通读一遍——12 条判例是 7 个 agent 定义 + 知识沉淀机制中所有「反直觉规则」的实证依据
- 培训新成员（或新 session 的编排者）时作为「为什么有这些规矩」的速答手册
- 本项目积累出自己的判例后，按 knowledge-capture 四模板逐条沉淀替换（保留判例作示例或删除均可）
