# 总索引与路由节模板（含单一权威源设计）

> 版本 v1.1
> 本文件是知识库**索引与路由的唯一规则权威**：所有行数上限、阈值、滚动规则只在下方「维护规则」节定义**一次**，其余任何位置（CLAUDE.md 路由节/agent 定义/文档）一律**单向引用不自报数字**。

## 〇、库边界定义（先于一切索引规则）

**知识库 = 目标项目 `.claude/skills/` 整体**——不设库中库、不另起库名：

- 总索引 README 与 drafts/ 建在 `.claude/skills/` **根下**（与 knowledge-capture/、methodology/ 目录并列）
- 收官扫描（Grep 症状词判「第 2 次同类」）与 Grep 兜底检索都以 `.claude/skills/` 全域为界——methodology 三 skill 同受覆盖，不产生扫描盲区；**两个例外口径：knowledge-capture/ 自身属机制元文档不计命中；命中判定以 frontmatter 与路由表行为先例，正文普通词命中不计**（防自指与假先例把加急常态化；Grep 兜底检索的可达性不受影响）
- 后续领域 SOP 直接在 `.claude/skills/<skill 名>/` 平铺新增，进总索引地图表

## 一、双索引分工（完整性与低摩擦的交换）

| 索引 | 角色 | 加载方式 | 内容 |
|---|---|---|---|
| 知识库总索引（`.claude/skills/README.md`） | **唯一权威全量表** | 按需 Read | 全部条目 + 状态 + provenance |
| 项目 CLAUDE.md 路由节 | 高频样例（性质是**副本**） | 每 session 自动加载 | 只放高频条目，滚动淘汰 |

防漂移规则（机制灵魂）：**明确声明谁是权威、谁是副本、副本按什么规则收缩**——两个索引没有主从关系必然渐次漂移。SOP 内容与路由分离也是双向的：CLAUDE.md 只放路由不放 SOP 内容；skills 只放 SOP 不放路由——内容在两处都出现就必然漂移。

> 教训固化（实战实测踩坑）：曾有项目 CLAUDE.md 路由节自称「硬上限 18 行」而知识库维护规则写「行数 ≤10」，两处数字不一致——这正是「契约冲突型」缺陷的活案例。本模板的解法：**数值只在维护规则处定义，CLAUDE.md 节不自报数字**。

```markdown

1. skill 自动触发（主通道）：description 写具体症状特征，任务匹配时自动加载

## 维护规则（★唯一数值权威——其余位置一律引用本节，不自报数字）

1. 新条目必加地图表行（skill 转正时同步更新状态列）
2. 地图表超 <地图表拆分阈值，建议 40> 行拆分（自然切面：按模板类拆分索引）
3. 季度复查：> <stale 阈值，建议 90> 天未验证标 stale；drafts/ 未采纳且超 <草稿清理阈值，建议 90> 天的草稿清理（清理前收官步骤兜底重扫呈报）
4. 采纳/失效判定一律人工（提炼者只做机械抽取与草稿，不做采纳决定）
5. 双索引分工：本表为唯一权威全量表；CLAUDE.md 路由节为高频样例（路由表含「最近命中」列，Claude 命中路由时顺手更新=机械锚；滚动保留近 <滚动窗口，建议 30> 天命中 + 新 skill 上市首 <滚动窗口> 天，行数 ≤ <路由节上限，建议 10> 行——**计量口径：表体行数，含表头，不含标题与空行**，满则**按最近命中日期**淘汰移出只留本表）——防两表渐次漂移
6. L2 skill 正文 ≤ <L2 正文上限，建议 150> 行（四模板转正条目同受此限；超限往该 skill 的 references/ 拆）
7. 单战役任务书「可沉淀知识」节 ≤ <可沉淀条数上限，建议 3> 条（每条一句话+出处）
8. Phase A 存量挖掘单批史料 ≤ <单批史料行数上限，建议 300> 行（防上下文溢出，见 §七操作卡）
9. 聚合升层（仅呈报）：同模板类且主题相邻的条目 ≥ <聚合阈值，建议 4> → 收官呈报附「建议聚合为方法论级条目」，人工裁决（聚合产物操作卡 v1.2 提供，本版不开自动通道）
10. skill 合规自检（发布前）：name ≤64 字符小写连字符；description ≤1024 字符；SKILL.md 正文行数 ≤ 第 6 条权威值且 ≤500 行官方底线；文件引用一律正斜杠
```

## 三、CLAUDE.md 路由节模板（引用不定义）

```markdown
## 知识路由（SOP 索引，v<N>，<日期>）

> <修复/处置/设计/审查>类任务**先查本表**，命中即 Read 对应 SKILL.md 再动手；
> 未命中且疑似新模式 → 按知识沉淀提炼规则产出草稿至 drafts/。
> 完整索引、状态、四模板附录与全部行数/滚动规则：`.claude/skills/README.md`（唯一权威）。
> 本节行数上限与滚动淘汰规则以该 README 维护规则为准，此处不自报数字。

| 症状/场景（触发词） | 先查 | 最近命中 |
|---|---|---|
| <错误码/行为样例短语> | <skill 名> | <YY-MM-DD> |
| <用户或 agent 会自然说出的短语> | <skill 名> | |

> 表行按维护规则的上限裁剪（不设示意尾行，防示意行被当作数据行或待替换占位符）。
> 即时通道机械锚：收到审查报告必 Grep 正文 `缺陷模式|普适|反模式|高危|Critical|High`
> （命中即判普适缺陷模式，当场落草稿）；采纳根因反转结论的同一回复内自查已按模板四落草稿或说明非反转。
```

行数预算实测口径（供项目自查上限是否形同虚设）：固定开销 = 引导 4 行 + 表头 2 行 + 机械锚 2 行 = 8 行，表行预算 = 上限 − 8——按此拆分预算。

## 四、路由触发词设计规范

- 触发词用**用户或 agent 会自然说出的短语**（「rc=0 但 0 行」「改了不生效」「两份文档说的不一样」），不用学术词
- 症状特征含错误码/表名/命令名/行为样例——精确串既提高命中又天然防误触发
- 每行一个 skill；同一症状多 skill 命中时选更专属的
- draft 状态的 skill 行内自带警告（「draft，仅供参考」）——状态警告放在最先被读到的位置

## 五、drafts/README 模板（最小规则集，复制即启动）

```markdown
# drafts/（未采纳草稿区）

- 定位：未采纳草稿——转正须用户显式批准，**未采纳零污染**（不进总索引/路由表/description 触发）
- 命名：draft-<模式名>-<YYMMDD>.md；头部标 origin=<review-round|reversal|wrapup> 与 呈报=<YY-MM-DD>#<次数>（每次收官呈报递增次数；≥2 次未裁决降频为每 3 次收官呈报一次，超期清理前必呈报保底）
- 正文按四模板之一组织（草稿与转正同构，转正=移动+总索引加行）
- 流转：①落盘前对照既有条目去重 ②双保险呈报（下一战役节点显式提及 + 季度清理前兜底重扫）
  ③采纳→转正；未采纳超期（阈值见维护规则）→季度清理 ④与现有条目矛盾标 CONFLICT 待人工，提炼者不仲裁
```

## 六、两个粒度的「草稿」辨析（防命名混淆）

| 粒度 | 含义 | 可见性 |
|---|---|---|
| **drafts/ 草稿** | 未采纳素材，门禁完全隔离 | 只有人工裁决流程可见 |
| **draft 状态 skill** | 已成型、进总索引、待首验或采纳门禁未过 | 可见但受限（description 内置警告） |

这是两级不同的灰度；通用体系显式区分，避免「draft」一词二义。

## 七、Phase A 存量挖掘操作卡（冷启动执行路径）

**冷启动豁免**：首批可用 methodology 三 skill + 判例精选为初始库直接开张，Phase A 可延后至项目积累可观数量史料（CHANGELOG/工作日志/战役报告）再执行——不因跳过它而阻塞知识库启用。

- **执行主体**：编排器派发轻档子 agent（平台通用 agent 即可，无专属角色对应）逐批执行；人工只做 Phase B 终审
- **分批规则**：史料按维护规则第 8 项的单批上限切批逐批处理（防上下文溢出），批间结果累积去重
- **挖掘 prompt 模板**（编排器逐批发给子 agent）：

```
扫描以下项目史料批次，找出重复出现的可复现处置模式。对每条候选输出：
症状（用户/agent 会自然说出的原话）/ 步骤（可复述的命令级步骤）/
出现次数与出处（文件:行号）。不做采纳判断。
与已有 skill 内容重复的标注「充实既有:<skill 名>」；仅有一次性价值的不输出。
判例数达到诞生门槛（knowledge-capture SKILL.md Phase B 节）才列为候选。
```

- **三值分流输出表**（子 agent 的固定输出格式，Phase B 只审前两类）：

| 判定 | 含义 | 去向 |
|---|---|---|
| 新 skill 候选 | 症状可命名 + 步骤可复述 + 判例达诞生门槛 | 草稿落 drafts/，待 Phase B 终审 |
| 充实既有 | 已有条目的新判例/新步骤 | 标注目标 skill 名，待 Phase B 终审 |
| 仅存档 | 一次性事实，无复用价值 | 不产出（留在 episodic 层不动） |

- **榨取不搬迁**：episodic 原文一律不改写，provenance 双向回指（见 SKILL.md 首批存量挖掘节）

## 八、草稿转正操作卡（用户说「采纳」时 Claude 执行）

**触发语样例**：「采纳 draft-XXX」「这条转正」「draft-XXX 转正」（引用 drafts/ 内具体文件名或收官呈报序号）。

**执行序列**：
1. Read 草稿全文，确认头部有 origin 行且正文按四模板之一组织；头部有 CONFLICT 标记 → 不转正，提示需先人工仲裁
2. 建目录并移动：`.claude/skills/<name 字段的模式名>/SKILL.md`（name=模式名本身，无前缀——与四模板 name 字段一致）。**结构必调一处**：草稿头行 origin= 位于 frontmatter 之前，转正时必须移到 frontmatter 之后改为 `> origin=<值>（转正保留）` 引用行——frontmatter 不在文件顶部会导致 skill 无法被识别；同时元信息「状态=draft」→「active」（采纳的直接语义）。除这两处外零改写
3. 总索引地图表加行：路径 / 症状触发词（取自 description 精华）/ 模板类 / 状态=active / 最后验证=今日 / 一句话用途 / 源材料
4. 删除 drafts/ 原件；回执一行：「已转正 <名> → 总索引地图表加行」

**转正条件**（缺一呈报待补，不强转）：①用户显式批准 ②判例 ≥3 或用户明示破例 ③≥3 个触发场景实测（description 命中且正文可执行）④去重核对过（与总索引及 drafts/ 现存无重复）
