# 盲重试反模式：回炉载荷必须携带阻塞级发现

## 缺陷模式（Pattern）

- **盲重试（blind retry）**：门禁 FAIL 后回炉任务书只传判定（"FAIL，去修"），不带失败反馈——执行者面对与首次完全相同的信息重做，成功率不优于基线

## 发现方法（How Found）

- 外部实证对照（Reflexion，arXiv 2303.11366）：带语言化反馈的重试比盲重试显著提升（HumanEval 80%→91%，+8pp；AlfWorld +22%）；**盲重试组在难任务上打不过基线**
- 反思记忆上限 1-3 条（防噪声灌爆上下文）——对应回炉载荷只带**阻塞级**发现原文，非阻塞只带计数

## 拦截案例（Case）

- 2026-10-02 optimize-v1 战役：方案审查发现本体系回炉语义原为"FAIL → 回炉"仅传判定——按上述实证补「回炉载荷规则」（手册 §3）：回炉任务书必含验证报告路径+全部阻塞级发现原文（或首步=Read 该报告节）；三份门禁 agent 报告头部固定置「阻塞级发现」节供回炉首读；implementer 收回炉任务书首步 Read 该节
- 同战役实践：方案审查 FAIL（C1/H3/M11/L6）与终验 FAIL（MISSING=3）两次回炉均携带阻塞级发现原文执行，一次修正即复审 PASS

## 适用场景（When）

- 任何多 agent/多步管线设计重试、回炉、返工机制时
- 人工评审流程同理：打回重做必须附具体意见，"不行重做"等于没说
