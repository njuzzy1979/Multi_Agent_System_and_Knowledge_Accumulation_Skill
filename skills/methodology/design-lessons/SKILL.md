# 设计教训库（选型论证纪律 + 设计红线）

## 核心教训（设计前先查）

1. **先查实存清单**：设计引用 agent/表/函数/配置键前 Grep 实存——知识漂移最常发生在「方案写的当天目标已退役/更名」。检查命令：`Grep <实体名> <代码根目录关键子目录>`
2. **选型排除必须留论证**：每个「不做 X」附排除理由 + 证据锚——否则每个新 session 重新论证一遍（调研成本重复支付）。排除论证写进「非目标」节，备选项进表格（备选/结论/排除理由三列）
3. **人机边界**：LLM 只做机械抽取（压缩/结构化/去重/路由），**采纳/失效判定/冲突仲裁留人**——错误知识污染所有未来 session 比没有更糟。（agent 知识体系的宪法级原则，同样适用于一切自动化决策：自动化只做无损变换，有损取舍留人）
4. **最小改动边界**：承诺「零行为变化」须逐字节验证（例：降级路径的重试语义与现状逐字节一致）；规格限定改哪层就在哪层；落点选择理由（内层/外层/哪个模块）写进实施报告——回炉与验证都以它为基准
5. **回滚方案完整性**：备份范围**逐项核对**（改动涉及几个存储/配置/状态就备几个；实例：备份漏掉两处关键状态存储，回滚只还原了主数据存储，漏备存储的变更需手动逆向）；git 管辖外的手工回滚点单列成表
6. **分批与审阅粒度设计**：大文本处理强制分批（防单次处理上下文溢出）；用户审阅只给**争议项与新提案**，全量清单不呈报（防审阅负担重演——这也是自反一致性判例：批判信息过载的方案自己不能制造过载）
7. **防御性设计**：半配/边缘态三分支显式覆盖——齐配/半配/未配置各有定义行为（示例：半配时告警一次后视为关闭，而不是每步都告警或静默吞掉）；「这层挂了系统行为是什么？答不出 = 漏洞」逐层自查
8. **审查预判清单**：方案定稿后、提交审查前，自查 review-patterns 五类缺陷模式（知识漂移/静默失败/审计断链/契约冲突/窗口期风险）——把审查缺陷前置到设计侧

## 修复 vs 废弃净效果评估

提议修复任何组件前先答：「修好了有没有人消费？」——无人消费的修复是负资产（改动面+回归风险换零收益）。配套问句：「这个机制当前的消费者清单在哪？修复后清单会变吗？」

## 文件写入红线（配套）

整文件重写一律**原子切换**，四条：

1. tmp 文件用唯一名（含进程号/时间戳——并发写者互不覆盖）
2. tmp **不得以目标扩展名结尾**（防 `read_parquet('*.parquet')` 类 glob 把写一半的 tmp 当正式文件读入；用 `.tmp`/`.part` 等独立后缀）
3. **多写入方共享同一文件 = 设计错误**（正确设计是独立文件隔离 + 单一归并者；共享必生竞态，只是早晚）
4. 统一**原子写 helper**，禁止各模块自行实现（三处以上自定义原子写=漂移起点）

（实例：tmp 命名踩坑致数据读者炸异常 + 多写入方竞态两判例。）

## 门禁/池设计附则（自举检查）

设计任何「候选池/门禁」机制时问：**「这个池的入口在哪？除了上次的自己还有谁？」**——入口只有单一历史路径的池是自举死锁（永远进不去新成员）。门禁三段式：probe（探测前置条件）→ marker（留下状态标记）→ 执行；跳过要留可区分的两种日志（「条件不满足跳过」vs「已处理跳过」）。

## 设计模板（提炼用）

决策 / 备选与排除理由 / 适用边界（模板二全文见 knowledge-capture 的 references/四模板.md）

## 禁止事项（红线）

- 非目标节只写「不做 X」不写为什么（决策回锅）
- 引用实体不 Grep 实存
- 回滚方案只写「恢复备份」不逐项核对备份范围

## 先例引用（provenance）

- 实例（2026-09）：知识体系方案 v1.0 设计/审查全链（四排除论证/亲历 H-1/M-3）+ 某降级兜底战役（三层落点理由/零行为承诺/三分支）+ 守卫复核 A4（回滚备份范围缺口）
- 本项目判例：在本节追加，格式=<日期｜战役/报告路径｜一句话结论>（源材料列随总索引地图表登记）

## 验证清单（Definition of Done）

- [ ] 方案含「非目标」节且每项带排除理由与证据锚
- [ ] 引用实体清单已 Grep 实存
- [ ] 回滚路径完整（含 git 外手工点）
- [ ] 五类缺陷模式预判已过一遍
- [ ] 半配/未配置分支行为已显式定义
