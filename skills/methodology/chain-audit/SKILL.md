# 链路测绘与复用面评估 SOP（侦查方法论）

## 适用场景（When to Use）

- 新 session 接手跨模块功能前的链路理解（生产侧/消费侧/历史值来源三类链路）
- 改造前复用面量化评估（多少直接复用/多少需改写）
- 排除逻辑留证（「为什么不是 X」）
- 缓存/过期数据识别

## 标准处置步骤

1. **三链路总图**：按「生产侧（谁产出它）/ 消费侧（谁读它）/ 历史值来源（存量从哪来）」画 ASCII 总图 + 逐环节文件:行号表。（实例：某数据回填战役的三链路图被后续实施/验证报告反复引用——**链路图是战役内其他环节的最快入口**）
2. **排除逻辑留证**：「为什么不是 X」每步写证据链（实例：「Grep 某库零命中之谜——不存在间接分发，靠 meta 字段分流」——零命中先找分发现径，不急着下「无引用」结论）；**「应该是没有」不算排除**
3. **复用面量化**：逐模块清单 + 语义替换表（实例：「1692 行中 ~1100 直接复用 / ~150-200 需改写」——**数字量化防拍脑袋重写**）
4. **缓存/过期数据识别三重证据**：逐位全同（两组不同对象 N 项指标完全一致，统计上不可能）+ 时间戳异常（同毫秒批量 vs 自然时序）+ 耗时异常（秒级返回 vs 真实计算应有的量级）——三重齐备才定谳「是缓存不是真数据」
5. **反直觉量化发现单独登记**：数字反常识即知识（实例：高频周期数据覆盖反而低于低频周期——降采样原料另有补充链在喂）
6. **复用面抽查**：抽 2-3 个「直接复用」模块实际 diff 验证——防评估乐观偏差（对 agent 产出的评估报告尤其必要）
7. **边角发现走登记簿**：侦查目标外的发现按「登记簿模式」流转，**禁止就地修复**（见下节）

## 登记簿模式（多 agent 编排的范围失控防线）

侦查中顺带发现的问题（未注册对象/口径断缝/同型隐患）一律登记，四字段：

| 字段 | 内容 |
|---|---|
| 发现内容 | 一句话描述 |
| 数据锚 | 文件:行号 / 查询结果 / 命令输出 |
| 风险对象 | 谁会受害（哪个消费方/流程） |
| 处置前提 | 什么条件下需要处理 |

三条流转路径：**升级待裁决**（影响当前战役结论）/ **挂靠既有任务**（已在某待办中）/ **风险留观**（暂不处理但可追溯）。禁止就地修复——侦查 agent 改代码 = 范围失控 + 证据链污染。

## 预设修正节（侦查报告必含，对抗确认偏误）

侦查报告必须含「**预设修正**」节：侦查前的预设（预期是什么）vs 实查结果（实际是什么）vs 差异解释。没有差异时也要显式写「预设与实查一致」——这个节让确认偏误可审计：读者能看到侦查者带着什么先验进来、哪些被推翻。

## 时间戳取证法（附则）

整表同毫秒 = 批处理写入；逐行自然时序 = 增量写入；混合分布 = 有回填历史。隔离实验法：逐项排除候选因素（每次只动一个变量），无法完全隔离时**定谳标准可降级**——修复正确性不依赖机制 100% 实锤（治本的收益不因根因只查到 90% 而作废）。

## 认知模板（提炼用）

先验假设 / 证伪证据 / 修正结论 / 方法论（模板四全文见 knowledge-capture 的 references/四模板.md；根因反转走即时通道 origin=reversal）

## 禁止事项（红线）

- 凭印象画链路图（每环节必须有文件:行号锚）
- 排除结论无证据链（「应该是没有」不算排除）
- 复用面只给定性不给量化数字
- 侦查中就地修复边角问题（走登记簿）
