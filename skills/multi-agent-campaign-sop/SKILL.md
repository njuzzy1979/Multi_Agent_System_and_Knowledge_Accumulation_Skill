# 多 agent 战役编排 SOP（并行分域 → 分级路由 → 终验 → 收官）

## 适用场景（When to Use）

- "全面审查/分析/修复/优化 X"类重型任务（跨多文件、多维度、需外部调研）
- 需要多 agent 并行但担心：输出灌爆主对话上下文、agent 静默死亡、编辑冲突、修复无人核对
- 三次实战战役验证的编排形态（先例见 provenance）

## 快速判定：任务 → 编排形态映射

| 任务特征 | 编排形态 | 分节 |
|---|---|---|
| 多维度审查/调研（读为主） | 并行多实例各独占一域 | §步骤 1-3 |
| 批量修复（写为主） | 分域派发 + 文件域互斥 | §步骤 4-5 |
| 修复后核验 | 单实例终验门禁 | §步骤 6 |

## 标准处置步骤

1. **分域派发**：把任务拆为互不重叠的文件域/主题域（防编辑冲突是硬约束），每域写自足任务书（背景/独占域/重点问题/工具纪律/**落盘路径**/极简三行回执格式）。同一消息并行派发全部实例（真并行）
2. **对账布防**：每个任务书指定 expect 落盘路径；派发后布防文件存在性监控（`until [ -f <path> ]; do sleep 5; done; echo READY`）——产物存在=完成的机械判定，不依赖 agent 自述
3. **回执路由**：收到极简三行回执按判定字段机械路由；读详情报告仅在做分级/修复规划时（防上下文回灌）；**战役计划先落盘 `<战役目录>/campaign.md`**（含状态行区——上下文压缩后的恢复锚）
4. **分级裁决**：汇总全部发现合并去重（跨报告重叠项合并处理）→ P0 阻塞/P1 直接修/P2 修后记录/P3 呈报用户决策不擅动。**裁决理由呈报给用户**（尤其二选一处）
5. **实施**：判断密集/跨文件一致性要求高的修复由编排器亲做（上下文全在手）；机械批量改写派子 agent（仍按文件域互斥）。编辑前重读目标区域（会话中文件可能被外部修改）。**回炉任务书必带阻塞级发现原文**（盲重试实证无效）
6. **终验门禁**：修复后派 code-validator，给它**逐条编号的修复清单**，要求三分法（MISSING/OVERSTEP/DEVIATION）+ 不采信实施自述；其轻微观察项若为一行修复可顺手修；FAIL 则按精确指引回炉后**targeted 复核**（不重跑全量）
7. **收官呈报**：判定台账 + 修复对照 + P3 待决清单 + 可沉淀知识（≤3 条）+ 对账确认（全部 expect 产物存在）+ 预算/选轨偏差归因（为零显式记「一致」）

## 禁止事项（红线）

- 不设 expect 产物就派发——静默死亡只能靠肉眼发现（违背对账初衷）
- 采信 agent 自述"已完成"而不验产物存在性
- 跳过终验直接收官——实战终验各抓获 1-4 处实施偏差（首轮 FAIL 回炉是设计内防线，不触发流程告警）
- 重叠文件域并行派发——编辑冲突 + 外部修改混淆
- 把 P3（需用户价值裁决的）擅自拍板

## 验证清单（Definition of Done）

- [ ] 全部实例回执收齐且 expect 产物存在（对账无悬空）
- [ ] 修复经终验 PASS（或偏差已按指引回炉+targeted 复核）
- [ ] P3 待决项全部显式呈报（无一沉默拍板）
- [ ] 可沉淀知识已按四模板落草稿或呈报
- [ ] 预算/选轨偏差已归因（零偏差显式记一致）
