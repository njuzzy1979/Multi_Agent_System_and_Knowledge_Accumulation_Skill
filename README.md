# 通用 Agent 体系与知识沉淀 Skill（v1.1）


## 这是什么

一套可直接复制到任何 Claude Code 项目的**多 agent 工程管线 + 组织知识沉淀机制**：

- **六件套管线**：侦查（并行 N 实例）→ 设计（可选）→ 对抗审查 → 实施 → 交叉验证 → 归档提炼
- **三大跨切面机制**（体系最强成分，整体可移植）：
  1. **输出契约**：落盘即遗忘 + 极简三行 final report（防子 agent 大输出回灌主对话上下文）
  2. **分派对账**：dispatch/done/expect/check 四事件协议（防 agent 静默死亡靠肉眼发现）
  3. **知识沉淀闭环**：四模板 + 双时机提炼 + 机械锚 + drafts 人工采纳门禁（防经验流失，更防错误知识污染）
- **红线域守卫模板**（domain-guard）：项目自声明的不可妥协域（资金/安全/合规/数据删除等）强制重档审查

> **适用边界**：以代码为主的项目最佳（管线语义围绕 diff/验证展开）；文档/数据项目接入可用但部分环节语义会拉伸。项目尚无 CLAUDE.md 时第二步直接新建即可。

## 解决什么问题

| 问题 | 体系的回答 |
|---|---|
| 长战役中主对话上下文被子 agent 输出灌爆 | 落盘即遗忘：详情 Write 到战役目录，final report 只允许三行 |
| agent 静默死亡 / 完成与否靠自述 | expect 产物存在性对账（文件存在=完成，比自觉回执强）+ 独立验证不采信自述 |
| 同一问题在不同 session 重复排查 | 知识沉淀闭环：episodic 记录提炼为 procedural skill，症状触发词路由两步定位 |
| 沉淀的错误知识污染所有未来 session | drafts 草稿区 + 人工采纳门禁：未采纳零污染，LLM 只做机械抽取 |
| 关键守卫规则「依赖自觉」必然失效 | 机械锚：收到 X 必做动作 Y（Grep/对照/落盘），触发器可机械执行 |
| 「成功」掩盖静默失败 | 验证区分正常成功/空转成功/降级成功三态；结论必须挂可复核证据 |

## 三步接入任何项目

**第一步：复制 agent 定义**
```
agents\*.md  →  <目标项目>\.claude\agents\
```
7 个文件直接复制。`domain-guard.md` 是模板——必须先填充正文全部 5 类占位符（红线域名/失败后果/检查项/影响单位/确定性防线）后才可用；复制进 `.claude\agents\` 即被注册，未填充时它处于 DEGRADED 保护态（工作流程第 0 步机械自检：残留 `{{` 字面量即降级交人工，不放水）；**项目无红线域时填「无」，domain-guard 天然休眠**。其余 6 个即复制即用（领域注入点运行时从项目 CLAUDE.md「项目上下文声明」节读取，未声明的键 agent 自行 Grep 代码推断）。若目标项目或用户全局 `~/.claude/agents/` 已有同名 agent（如 adversarial-reviewer），按实战判例精选判例 10「补丁节合并」接入——把本包通用纪律节追加为既有版补丁，不整文件覆盖。**工具面**：六份定义已声明 `tools` 白名单（门禁类只读+报告落盘），在 Claude Code 宿主为平台强制，其他宿主无害退回行为约定。

**第二步：粘贴 CLAUDE.md 集成段**
打开 `skills\knowledge-capture\references\CLAUDE.md集成段.md`，把其中四节（Agent 调用规则 / 知识路由 / 知识沉淀提炼规则 / 项目上下文声明）粘贴到目标项目 CLAUDE.md 尾部，替换 `{{占位符}}`。

**第三步：搭知识库骨架**
```
skills\knowledge-capture\    →  <目标项目>\.claude\skills\knowledge-capture\
skills\methodology\          →  <目标项目>\.claude\skills\methodology\
```
**知识库根 = `.claude\skills\` 整体**（不设库中库）：本包 skills\ 目录已含预建总索引 `README.md` 与 `drafts\` 骨架——**复制即得，无需重建**（冷启动即以 methodology 三 skill + 判例精选开张；首批领域 SOP 按 Phase A 机械初筛 → Phase B 人工终审从项目 CHANGELOG/工作日志挖掘，操作卡见 `索引与路由模板.md` §七，Phase A 可延后）。目标目录已有同名 skill 时，先把已有版重命名为 `<名>-legacy` 再复制，并在总索引登记待人工合并（不静默遮蔽既有内容）。建议把战役报告目录（如 `results/`）加入目标项目 .gitignore——工作产物不入库。

**接入手册**：编排器语义、对账协议、档位分配 → 读 `skills\knowledge-capture\references\六件套管线手册.md`（随第三步复制到目标项目内，路径自洽）。

**第 0 步自检（接入完成后跑一遍，确认体系就绪）**：①让 Claude 列出已注册的本包 7 个 agent 名（确认注册生效）；②派一个 eng-recon 最小试跑（子模式 tech、目标随意、落盘临时路径），验证派发链路与极简三行回执；③Grep 集成段残留 `{{` 确认占位符已处理。三步全过=体系就绪；任一失败按手册 §6 对账排查。

## 升级 / 卸载 / 用户操作卡

**升级（本包发新版时）**：①agents 升级=用新版通用骨架**重放补丁节**（判例 10 机制化：把你接入时追加的领域补丁节重新合入新版，不整文件覆盖）；②集成段升级=**覆盖稳定规则前，先摘取旧版三处占位符现值（红线域/触发点清单/战役报告目录），覆盖后回填**（占位符区属活配置）；③知识库条目兼容=各 SKILL.md 尾部元信息「适用版本」对照，不兼容条目按 stale 流程复查。

**卸载**：反向三步——删 `.claude\agents\` 下本包 7 文件、CLAUDE.md 删集成段四节、删 `.claude\skills\` 下 knowledge-capture/ 与 methodology/ 两目录。**注意：你的领域 SOP（其他 skill 目录）与 drafts/ 是你的资产，默认保留**。

**用户操作卡（日常你只需要做三件事，其余是 Claude 自治域）**：
1. **收官裁决**——每次战役收官呈报里的待采纳草稿 / P3 待决项 / DEGRADED 介入，说"采纳/否决/怎么改"
2. **维护红线域触发点**——项目新增资金/安全类入口时，更新 CLAUDE.md 硬性规则 1 的触发点清单
3. **季度批量裁决**——收官呈报中超期草稿与 stale 条目的复查建议，批量拍板

> 体系内其余概念（战役/档位/对账/机械锚/四模板/双索引…）均由 Claude 消化执行，无需理解即可用。

## 边界与运维

**多项目**：本体系按项目独立部署（知识库=各项目自己的 `.claude/skills/`）。通用类 skill 若放用户级 `~/.claude/skills/`，则**该条目不参与项目库索引与收官扫描，其治理随宿主**（升级一处生效、不进项目总索引——显式划界，不做默认兼容）。跨项目流转一条 SOP = 复制 skill 目录到目标项目 + 目标总索引加行 + 源材料列标注来源项目。

**并发与备份**：多 session 并行时 draft 命名加时间戳后缀防同日碰撞（如 `draft-<名>-<YYMMDD>-<HHmmss>.md`）；建议把 `.claude/skills/` 整体纳入目标项目版本控制（drafts/ 可选忽略）——换机/回滚不丢沉淀。

## 核心设计决策（为什么长这样）

1. **侦查合并为单文件三子模式**：早期版本三个侦查 agent（技术/数据/调研）核心纪律高度重叠（查证不猜测/精确数字/引用必验证）。合并后编排器仍可并行派 2-3 个 eng-recon 实例各带不同子模式任务书——「并行的是实例，不是定义」。依据：调用痕迹治理判例（agent 定义是负载不是资产）。
2. **对抗审查随包分发**：管线表③直接引用 `adversarial-reviewer`——若不随包分发，三步接入完成后首次派发即断链（agent not found）。故作为第 7 个 agent 文件随包（默认纪律由定义承载；重点域与红线域标注仍由任务书给定）；项目已有同名 agent 时优先项目版（同名双轨）。
3. **单一权威源**：行数上限、阈值等数值只在知识库 README 维护规则处定义一次，CLAUDE.md 路由节单向引用不自报数字——曾有体系实战中出现两处数字不一致（18 行 vs 10 行）的契约冲突，本设计根治。
4. **知识提炼机制不内嵌在 documenter 定义里**：四模板/drafts/呈报协议属体系级机制，统一由 knowledge-capture skill 承载；documenter 只做机械路由调用。理由：机制放 agent 定义会导致双份定义漂移。
5. **数据质量验证并入 validator 配置档**：早期版本中独立数据质量 agent 三周出场 ≤2 次（常规验证已由 validator 承担），故降为 validator 的「数据验证档」而非独立角色。

## 使用原则（克制清单）

- 不引入外部框架（不装 LangChain/LangMem 等依赖，只借概念）
- 不建向量知识库（百条级 markdown + grep + 索引三方交叉验证优于 RAG）
- 不做全自动采纳（人工门禁是安全机制不是性能瓶颈）
- 新增 agent 角色必须有调用痕迹预期，周期复盘按实际痕迹清退（死定义清理判例）
