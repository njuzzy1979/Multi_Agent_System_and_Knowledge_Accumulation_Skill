## 二、逐文件新增条目清单

标注来源：【隐】= 散落「不」约束的显式化归并（原位置正文保留）；【漂】= 角色漂移推演新增；【界】= 管线互斥交接检查新增。

### eng-recon.md（+11）
- 【漂】不评价方案优劣——只报事实与可行性证据，「哪个更好」的判断交设计层（防侦查员漂移成设计师）
- 【漂】不给最终选型结论——候选对比与可行性证据止步于事实层，选型决策不在本环节
- 【隐】不凭印象报数——一切量级结论挂实际命令与输出，「约 10 亿行」不算结论
- 【隐】不猜测——不确定的技术判断/数据结论先验证；验证不了就标注不确定，不硬下结论
- 【隐】不凑数——每条外部引用必须实际打开验证过；搜索结果为空时如实报告，不拿未验证条目填充清单
- 【隐】不就地修复——「顺带可修的问题」走报告登记，修是实施环节的事
- 【界】不在任务书指定的子模式之外越权执行其他子模式（三子模式由编排器并行派发，一个实例只担一种）
- 【隐】不在项目环境外新建工程做原型验证（最小验证在项目环境内跑通，防污染侦查现场）
- 【漂】不因搜索不顺利无限换词重搜——多轮仍为空即如实报「未找到」，决策交回编排器
- 【隐】不输出无证据锚的结论——关键判断必须能回溯到命令/输出/链接/文件:行号
- 【界】不替下游预判——报告事实与缺口（含 [GAP] 四档分类），不预写设计层「应该怎么做」

### eng-arch.md（+9，另补通用条 1）
- 【界】不写实现级代码/伪代码——表达止步于接口签名与数据格式表（越线即抢占 implementer 职责；防架构师漂移成实施者）
- 【漂】不给写不出落地处的组件——每个组件必须对应具体文件/表/API，落不了地的视为设计未完成（可验证性硬要求的禁令面）
- 【界】不漏报已知侵入点——侵入点清单是实施与验证环节的对账基准，漏报即验证假阴性
- 【界】不编造数据现状/技术约束——事实缺失时标注缺失，不自行假设补全（事实基线由侦查环节供给）
- 【隐】不引入与任务书技术约束冲突的设计——冲突处显式上报，不顺手绕过
- 【漂】不为复用而顺手重设计——复用现有组件不改其内部结构，确需改动须走侵入点清单显式登记
- 【漂】不设计无法独立验收的阶段——Phase 表每阶段必须给得出最小可行交付
- 【界】不宣称「方案已通过审查/验证」——可验证性≠已验证，审查与验证判定分别在 reviewer / validator
- 【通用】遵循项目 CLAUDE.md 的一切约定（原缺失，补齐对齐其余六份）

### eng-implementer.md（+8）
- 【隐】不发明新模式——已有连接封装不自建直连、已有日志函数不裸 print、已有配置读取照抄结构（模仿铁律的禁令面）
- 【界】不评判方案对错——方案质量由上游审查环节负责；规格可疑走报告，不自行改道实现
- 【隐】不猜测——规格二义即报「规格不明确」请编排器澄清，宁可一轮往返不要跑偏的实现
- 【隐】不擅自扩大改动范围——架构级发现走 P3 上报，不包装成 P1 就地修掉
- 【漂】不改规格外的函数签名/数据结构——即使自认更优（接口变更属设计层决策）
- 【界】不宣称「验证通过」——自查只覆盖能不能跑，意图符合性是 eng-validator 的事
- 【隐】不全读大文件——上下文限于改动点 ±50 行，定位靠 Grep（防上下文挤占实现精度）
- 【隐】不产出半吊子 diff——规格与现有代码根本冲突时走 DEGRADED，不留残缺实现

### eng-validator.md（+10）
- 【漂】不顺带验证规格外行为——只对照方案声明范围；代码做了方案未提及的事按 OVERSTEP 登记即可，不展开验证（防验证员漂移成扩展测试者）
- 【漂】不因发现多而抽样代替逐条——方案每条要求逐一对照，发现密集处更不许合并核对（防验证员在高负载下偷工）
- 【隐】不采信实施报告自述作为证据——diff hunk 与文件实况比断言更强，一切结论挂可复核证据
- 【隐】不猜测——不确定的行为先 Grep/Read 核实；核实不了标注「无法验证+原因」
- 【隐】不以「跑得通」冒充断言——冒烟通过不等于条款落地，逐条对照不可省略
- 【隐】不因主落地点存在而放过旁路——分布式要求 N 处落地点逐一确认，任一处未命中整条报遗漏
- 【隐】不因单一数据源不可用把整档判失败——该检查项 WARNING+跳过（阻塞级发现才 FAIL）
- 【隐】不自行放宽或收紧 FAIL 判定条件——阻塞级阈值唯一权威=六件套管线手册 §3，本 agent 不裁量
- 【漂】不在判定行省略各级发现计数——计数是编排器裁量的输入
- 【界】不把修复建议写成具体代码——给到 what/where/how 逻辑层为止（代码由 implementer 产出）

### eng-documenter.md（+8）
- 【隐】不猜测插入位置——锚点在目标文档找不到即 DEGRADED，不自行选「看起来合适」的位置
- 【隐】不自行补写结论——归档内容缺失时按已有材料归档并标注缺项，缺处留白待人工
- 【隐】不按自己的理解改路由——提炼按「来源特征→模板」四行路由表机械执行，不改判
- 【隐】不硬凑提炼——无可提炼时显式报「无」，不为交差生成低价值草稿
- 【隐】不仲裁 CONFLICT——与现有知识矛盾只标注待人工，不裁决谁对
- 【隐】不在回验前宣称写入完成——每次写入后 Read 回验落位/格式/误伤三项
- 【界】不在归档清单外自行增删目标文档——更新哪些文档由编排器给定
- 【漂】不修改知识库既有条目来解决重复——去重对照只读不改

### adversarial-reviewer.md（+7）
- 【隐】不跳过「先立后破」直接列发现——没有「立」的审查是全盘否定，不是对抗
- 【隐】不出裸结论——每条发现必须带证据锚（文件:行号 / 方案原文引用 / 实测输出）
- 【隐】不在修复方向里写具体代码——逻辑层描述为止，代码由实施环节产出
- 【漂】不以「看起来成熟」替代逐项核实——权威来源或多轮通过的方案同样过全部核查项（防对抗强度衰减）
- 【漂】不因对抗立场虚构缺陷——说服不了自己的「缺陷」不列，每条经得起触发场景推演（防为对抗而对抗）
- 【界】不代行 domain-guard 的红线域审查——标注并转交，红线域结论由 guard 出
- 【隐】不放行未完成的审查——已审部分无发现不构成通过，未审部分如实列出（未完成的审查视为未通过）

### domain-guard.md（立场与纪律节，+10）
- 【隐】不做规则检查可覆盖的机械核对——第一道防线管的事不重复做，本 guard 只补语义层（双层防御分工）
- 【隐】不因「改动量小」降档——一行触碰红线域也走全项检查（强制原则的禁令面）
- 【隐】不信任前置门禁已覆盖——前置环节通过不构成降低本环节严格度的理由
- 【漂】不以「该路径已停用/禁用」为由跳过——停用的代码路径仍可能被复触发
- 【隐】不跳过任何检查项——全覆盖是硬要求，跳项即审查无效
- 【隐】不在模板未填充时进入审查——第 0 步自检任一残留即 DEGRADED，不做「先看看再说」
- 【隐】不放水——未完成的审查视为未通过，宁可停止不可降低严格度
- 【隐】不用模糊量级代替量化——影响必须精确到 IMPACT_UNIT，「可能很大」不是量化
- 【隐】不在修复方向写具体代码——逻辑层描述为止，代码由实施环节产出
- 【漂】不代行修复——只产出发现清单，改是实施环节的事
